# NSE closing crossover scanner build plan

Verify one NSE cash equity end to end, expand to a fixed 30-stock watchlist, then operate the full scanner unattended. A deterministic Python worker runs the same strategy for historical replay and forward scans. SQLite stores inputs and results, FastAPI exposes them, and React with TypeScript displays them. Angel One supplies candle data and can supply holdings through a separate optional refresh. The application exposes candle and holdings reads and hypothetical trades.

## 1. Freeze the pilot rules

| Decision | Pilot rule |
|---|---|
| Universe | Configure one NSE cash equity by exchange, series, symbol, and verified SmartAPI token. Choose a liquid symbol with enough daily history. The corporate-action fixture may use another equity. |
| Signal | Use finalized daily closes in NSE session order. An up-cross occurs when the previous 20-session SMA was at or below the 50-session SMA and the current 20 is above the 50. A down-cross occurs when the previous 20 was at or above the 50 and the current 20 is below the 50. Equality today triggers neither. Require 51 valid closes and account for every intervening exchange session. Skip an exchange-confirmed no-trade session when counting closes. |
| Position | Start flat with an explicit opening cash balance. Enter only on an up-cross while flat and exit on a down-cross while long. Record detected crosses and their dispositions, including a down-cross while flat. Keep at most one hypothetical position per stock. |
| Fill | Target the next NSE trading session's raw open. Apply adverse slippage and configured fees. Size in whole shares so the entry, including fees, fits the fixed per-position allocation and remaining cash. Record insufficient-cash and zero-share skips. |
| Portfolio | Use one cash ledger. At each open process exits before entries, then use stable symbol order within each group. For the simulator, net exit proceeds are available for same-open entries. Mark open positions at the close. Use decimal currency arithmetic with a documented final rounding rule. |
| Price basis | Retain raw OHLCV. Use split- and bonus-adjusted closes for the SMA based on actions effective by that session. Use raw prices for fills and marks, and apply verified share changes before trading on the effective session. Account for cash dividends consistently in both portfolio and benchmark, or label the pilot as price-return-only and exclude dividends from both. Choose and record the policy before replay. Flag unresolved actions and suspend affected calculations until resolved. |
| Run identity | Persist strategy version, watchlist version, run mode, opening cash, allocation, fee and slippage configuration, calendar version, and the candle and corporate-action versions used. |

## 2. Build the one-stock pilot in order

1. **Scaffold the application.** Create the Python strategy and portfolio modules, SQLite migrations, and CLI commands for backfill, replay, and session scans. Add FastAPI and a minimal React dashboard after the worker can run from the CLI. Keep the strategy and simulator independent of the web server and broker adapter.
2. **Connect SmartAPI and verify inputs.** Build the backend adapter for authentication, token lookup, and daily candles. Keep credentials and tokens out of the frontend and redact them from logs. Fetch the warm-up and the replay period in bounded, rate-limited batches. Compare at least five daily OHLC rows with NSE bhavcopy, including a normal session and sessions around a known split or bonus in a reference instrument. Check how SmartAPI represents the action before choosing any normalization. If a reliable raw price or verified adjustment is unavailable, stop the affected calculation and surface the reason. [Angel One SmartAPI documentation](https://smartapi.angelone.in/docs) · [NSE reports and bhavcopy](https://www.nseindia.com/all-reports/)
3. **Persist enough to reproduce a run.** Store instruments, trading sessions, versioned candles, corporate actions, run attempts, per-symbol outcomes, crosses, pending fills, completed fills, cash movements, and daily equity. Record each candle's session, source, and first-observed time. Scope unique signal and fill keys to the portfolio or replay, instrument, strategy version, and signal session. Link each fill to its originating signal and opening candle. Commit each finalized session in one transaction and prevent overlapping writers for the same portfolio. Support replay from stored inputs.
4. **Implement the session cycle.** For session D, resolve eligible fills at D's open, mark positions at D's close, then evaluate new crosses for the following session. Validate the candle date, duplicates, OHLC consistency, and continuity against the NSE calendar. Return a visible status for every instrument. Missing or invalid inputs keep the session provisional and trigger a bounded retry. After the retry cutoff, alert and keep the committed ledger at its last complete session while the gap is unresolved. On a confirmed no-trade session, carry the last available mark on the current share basis, label it stale, and skip signal evaluation for that stock. Recover sessions in chronological order. Preserve committed forward history and report any later source correction separately. [NSE market timings and holidays](https://www.nseindia.com/resources/exchange-communication-holidays)
5. **Implement forward timing.** Persist the actual first-observed timestamp of every forward cross. A cross discovered at or after its intended open is recorded as late and receives no fill at that open. The pilot skips a late entry. For a late exit on an open position, target the first subsequent trading session whose open is still in the future when the signal is recorded. A missing opening candle keeps an eligible fill pending verification. A confirmed no-trade open cancels an entry and defers an exit to the next eligible session, with the reason recorded. Historical replay applies the same strategy and accounting to a separate portfolio assuming inputs were available at the modeled times.
6. **Expose the one-stock result.** Serve run status, the latest validated session and both SMAs, signal and fill details, and hypothetical cash, positions, equity, and P&L. Show signal and fill markers on their own sessions and display the reason for any pending, late, skipped, or failed outcome. Show the last finalized portfolio session when a newer scan is provisional.
7. **Run the scheduled pilot.** Use Asia/Kolkata and the NSE session calendar, including special sessions. Start after the expected candle publication window and verify availability before finalizing. Use bounded retries for transient broker failures and an alert or health check for stale data, failed scans, and missed runs. Test the intended host's login flow across midnight and verify that the next scheduled scan succeeds without manual intervention. [Angel One SmartAPI authentication](https://smartapi.angelone.in/docs)

## 3. One-stock acceptance tests

| Test | Pass condition |
|---|---|
| Real candle backfill | The configured token resolves to the expected NSE equity and series. The sampled OHLC rows match the reference at source precision or any discrepancy is resolved and documented. The first evaluated session has both SMA comparisons available. |
| Crosses, warm-up, and starting position | A deterministic fixture produces one up-cross and one down-cross. Test previous equality, current equality, several sessions above the slow SMA, insufficient history, a missing session inside the SMA window, and a first eligible session already above the slow SMA without a fresh cross. A down-cross while flat creates no fill. |
| Fill and cash reconciliation | With ₹1,000 cash and allocation, use 50 closes at ₹100, then closes of ₹110 and ₹80 on sessions 51 and 52. The worker signals entry on 51 and exit on 52. Use opens of ₹112 and ₹90 on sessions 52 and 53, adverse slippage of ₹1 per share, and a ₹2 fee per side. Expect eight shares bought at ₹113, ₹94 cash left, ₹734 equity at the session 52 close, and sale at ₹89 on session 53. Final cash and equity are ₹804, with net P&L of −₹196. Reconcile the API and UI to those values. |
| Corporate action | Replay a verified split or bonus across an open position. Confirm adjusted SMA history, share quantity, valuation, and that the mechanical price change alone creates neither a cross nor a portfolio gain or loss. Verify the chosen dividend policy in the ledger and benchmark before reporting benchmark results. |
| Calendar and missing data | A weekend or holiday pushes the fill to the next trading session. A special session follows its calendar entry. A stale, missing, or invalid candle produces a visible status and no finalized ledger advance. A confirmed no-trade open follows the entry cancellation or exit deferral rule. |
| Timing and restart | A signal first seen after the target open follows the late-entry or late-exit rule. Simulate a crash before commit, restart, and rerun a committed session. The recovered ledger matches a clean run with the same inputs and observation times, with zero duplicate signals, fills, or cash movements. |
| Broker and scheduler | Exercise an expired session, a throttled request, and a missed run. Verify retry and alert behavior and that recovery preserves the ledger. Record three consecutive scheduled NSE sessions with valid outcomes, including an automatic login after a midnight rollover. |
| End-to-end trace | From a dashboard fill, trace the signal session and observed time, candle data, opening price, slippage, fee, and cash and equity changes. The same views show a failed or provisional session clearly. |

**Gate to expand to 30.** Pass every applicable pilot test and save the fixture results, real candle comparisons, ledger reconciliation, and scheduled-run evidence. Use replay or fixtures to exercise both cross directions and a completed round trip. The scheduled live-data check can pass on sessions with no crossover.

## 4. Expand to 30 stocks and release

1. Configure and verify the 29 remaining tokens. Freeze a versioned 30-stock watchlist and the strategy before evaluating the holdout period. When replaying today's picks on earlier data, label the result accordingly. Define the benchmark as a buy-and-hold basket of the same watchlist over the same evaluation period, with explicit initial weights, entry timing, costs, dividend treatment, and residual cash.
2. Test shared cash before enabling the full scheduler. Simulate one missing exit candle with two entries competing for the proceeds. Confirm the dashboard shows each symbol's provisional outcome, the ledger stays at the last finalized session, and recovery produces the same fills and skips as a clean run with the same inputs and observation times. Also test a known no-trade open and two overlapping scan attempts.
3. Complete the dashboard with the 30-symbol watchlist, stock details, hypothetical trade log, net P&L, equity curve, drawdown, the benchmark, and scan health. Add optional actual Angel One holdings as an independent refresh and view. A holdings failure must leave scanner results available.
4. Run the 30-stock scanner unattended. Require a recorded outcome for all 30 symbols per scheduled session, correct alerts for gaps, zero duplicate ledger events on retry, and an audit trail for every fill and skipped entry. Review after-cost holdout results and completed forward trades before deciding whether to scope a later live pilot.
